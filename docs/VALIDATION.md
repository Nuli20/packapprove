# Проверка в облачном окружении · 24 октября 2026

Проверено на Node.js 24.19.0, npm 11.9.0, PostgreSQL 17.6, настоящих Supabase Auth v2.186.0 и Storage v1.35.3, системном Chromium. Docker Compose использует зафиксированные версии образов; зависимости npm зафиксированы lockfile.

| Проверка | Результат |
|---|---|
| Установка `npm ci` | Выполнена успешно |
| Повторный `npm run local:up` | Сервисы готовы; существующие данные сохранены |
| Полная SQL-миграция | Применена с ON_ERROR_STOP в отдельной пустой базе с платформенными схемами Auth/Storage; проверочная база затем удалена |
| `npm run typecheck` | Пройдено |
| `npm test` | 20 реальных интеграционных тестов пройдено |
| `npm run test:e2e` | 6 сценариев пройдено, Chromium desktop и mobile |
| `npm run build` | Production-сборка успешна |
| Production runtime | Проверены вход, авторизованный RLS snapshot и private file download с SHA-256 |
| Некорректный JSON | HTTP 400 |
| Потоковый oversized body без Content-Length | HTTP 413 |
| `npm audit --omit=dev` | 0 известных уязвимостей на момент проверки |
| Deadline reminders | Повторный запуск не создаёт дубликаты |
| Private bucket | `artworks.public = false` |
| Demo после очистки TEST/E2E | 3 клиента, 5 проектов, 8 макетов, 12 версий, 10 профилей, 2 комплекта |

Интеграционные тесты проверяют исходные 13 инвариантов, а также неизменяемость решений администратора, MIME/size, перенос замечаний, optimistic locking проекта, запрет скачивания production files клиентом, запрет приглашения администратора менеджером и принятие одноразового приглашения с реальным Auth account.

Браузерные сценарии создают новые проекты и раунды через HTTP API, выполняют клиентское решение через UI и проверяют сохранение после reload. Рендер PDF проверяется после завершения canvas render, а не только по существованию элемента. Проверены координатные комментарии, русская/казахская локализация и отсутствие внутренних веток у клиента. PNG и traces сохраняются в игнорируемом test-results; HTML отчёт — playwright-report.

Проверялась текущая машина. Настройки `install_script` и `start_skill` сохранены в черновике cloud environment. Публикация пользователем и восстановление в новой облачной задаче не выполнялись. Внешний managed Supabase, SMTP, ERP, нагрузочное тестирование, penetration test и disaster recovery drill не проверялись. Границы MVP описаны в README и docs/ARCHITECTURE.md.
