# Демо-кабинеты PackApprove

`/demo` — отдельный вход в шесть рабочих кабинетов. Он использует реальные Supabase Auth sessions, PostgreSQL и RLS. Роли не подменяются в интерфейсе, API не заменяется fixture JSON.

## Изоляция

Демо-вход разрешён только при `NEXT_PUBLIC_DEMO_MODE=true` **и одновременно** DATABASE_URL → localhost/127.0.0.1:54322/postgres, SUPABASE_URL → http://localhost/127.0.0.1:54321. Проверка повторяется на сервере перед входом. Один UI-флаг не включает демо против облачной production-базы. Роль после Auth login повторно проверяется по активному RLS-профилю; повышать/создавать роли или менять production-пароли этот endpoint не умеет.

Это полностью работающий **изолированный локальный стенд** в облачном окружении разработки. Публичная демонстрация всех ролей на удалённом Supabase в этой версии не включена: для неё нужны отдельный Supabase project, проверяемый механизм допуска тестового deployment и отдельные секреты. Production-переменные не переключались. Публичная `/can-lab` по-прежнему работает отдельно и без базы.

## Запуск подготовленного стенда

В текущем cloud workspace Docker уже установлен; установка на компьютер пользователя не требуется. `npm run local:up` запускает службы и выполняет три идемпотентных seed-команды. Если службы запущены, достаточно `npm run db:setup`, `npm run seed`, `npm run seed:cans`, `npm run seed:workflow`, затем `npm run dev`.

Seeds работают только на локальной demo-среде. Новый workflow seed создаёт отдельные проекты и не заменяет существующие клиентские или предыдущие демонстрационные проекты. Повторный запуск сохраняет готовые проекты. Если демонстрационный сценарий изменён пользователем, seed не сбрасывает его молча.

## Кабинеты

| Кабинет | Подготовленный аккаунт локального стенда | Что открыть |
|---|---|---|
| Администратор | admin@packapprove.local | Команда, приглашения, заказчики, пошаговая форма проекта |
| Менеджер | manager@packapprove.local | Заказы, согласования, готовность и передача |
| Дизайнер | designer@packapprove.local | Назначенные макеты, версии и исправления |
| Допечатная подготовка | prepress@packapprove.local | Очередь SAIA V2, чек-лист и технические комментарии |
| Клиент-согласующий | can-approver@packapprove.local | ZHYRA, сохранённый дизайн в 2D/3D, замечания и решение |
| Производство | production@packapprove.local | Комплект TUN, точный файл, SHA-256 и подтверждение получения |

Пароль вводить не нужно: карточка роли на `/demo` выполняет обычный серверный Auth login и устанавливает HttpOnly cookies. Для ручного локального входа прежний demo-пароль указан в README. Эти аккаунты не создаются в production.

## Учебные заказы

Дополнительно подготовлен **ZHYRA / подготовка дизайна, 450 мл**: V1 зафиксирована, но ещё не отправлена на проверку. Это реальная задача дизайнера; он может открыть её, создать новую версию или передать V1 допечатнику. Клиент не получает неопубликованный файл.


- **ZHYRA / Цитрус, Standard 450 мл**: первая версия прошла техническую проверку и ожидает решения клиента.
- **SAIA / холодный чай, Sleek 330 мл**: клиент запросил изменения V1; дизайнер создал V2 с другим настоящим PNG, перенёс открытое замечание и отправил на внутреннюю проверку.
- **TUN / энергетический напиток, Slim 250 мл**: техническая проверка и клиентское решение завершены; менеджер передал комплект, производство может скачать и подтвердить SHA-256.

Во всех проектах есть клиентские и внутренние комментарии. Клиент не получает внутренние обсуждения. Геометрия приблизительная, бренды вымышлены; demo ready-check не является реальным допуском к печати. Предыдущие Tea House fixtures сохранены для регрессионных сценариев.

Рабочая последовательность: проект → макет → конкретная версия → 2D / 3D / сравнение → комментарии → согласование. `/can-lab` больше не вынесена в основную навигацию кабинета; отдельная демо-сцена доступна со страницы выбора ролей и авторизации.
