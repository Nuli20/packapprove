# Showcase: шесть напитков

Ветка создана от `main` (`50688b3`, после PR #5). Импорт не запускается при сборке,
деплое, `local:up` или входе. Миграций и новых переменных окружения нет.

## Как увидеть проекты в опубликованном кабинете

1. После проверки и разрешения владельца опубликовать эту ветку через PR в main
   и дождаться Ready у Vercel. До публикации новые кнопки на старом сайте отсутствуют.
2. Войти существующим администратором → **Проекты → Добавить демо-проекты**.
3. Просмотреть шесть концепций и предупреждение DEMO. Выбрать существующих активных
   дизайнера и допечатника из организации производителя. Если их нет — сначала
   пригласить в **Настройках**, завершить регистрацию и повторно открыть импорт.
4. Подтвердить демонстрационный характер и нажать **Добавить шесть проектов**.
5. Найти `DEMO / SOLAR POP`, `MIRA BERRY`, `VOLT X`, `LUMA TEA`, `TERRA WATER`,
   `PINK WAVE`. Открыть проект → макет либо ссылку **Открыть версию в 3D** в карточке.
   Файлы, версия, 2D, 3D и сравнение используют существующий рабочий интерфейс.

Повторный импорт возвращает прежние ID, не заменяет файлы, названия и назначения.
Это общая коллекция производителя, не отдельная копия для каждого администратора.
Существующие заказы, в том числе «Кола Зеро», не используются для поиска или записи.

Публичная `/can-lab` доступна без входа: три прежних дизайна сохранены и добавлены
шесть новых. Есть 2D, 3D и PDF; публичная страница использует только статические
публичные файлы, не API проектов и не приватный Supabase Storage.

`public/showcase` содержит девять PNG, девять PDF, девять исходных SVG, манифест
и привязки SHA-256. PDF имеет физический размер соответствующей печатной области;
это RGB-визуализация, не CMYK-цветопроба и не заводской технологический шаблон.
Везде есть **DEMO — NOT FOR PRODUCTION**; нет настоящих штрихкодов, адресов или
недостоверной обязательной информации. Вторая версия меняет служебную типографику.

Для воспроизводимой генерации: `npm run demos:showcase` (Chromium, переменная
`CHROMIUM_PATH` при другом расположении браузера). Генератор сохраняет старые
привязки хешей, чтобы опубликованные сохранённые файлы не теряли формат.
Он не обновляет уже импортированные неизменяемые версии.

## Безопасность и архитектура

`showcase.import` — отдельная узкая команда администратора для фиксированных
публичных концепций. Она использует существующий `execute`, проверку актуальной
роли, rate limit, idempotency key, `asUser`/RLS и создание проектов через
`projectCommand`. Администратор не получает права на обычный `version.create`
или клиентское решение. Входные данные не позволяют загрузить произвольный файл,
указать путь Storage, автора решения или статус согласования.

В одной PostgreSQL-транзакции создаются шесть организаций DEMO, проекты,
назначения, задания, версии и записи файлов. Байты загружаются в существующий
приватный bucket с UUID, фактическим MIME и SHA-256. При ошибке транзакция
откатывается; уже загруженные объекты удаляются при обработке ошибки.
Глобальная advisory lock и неизменяемые записи `showcase.project.created` с slug
защищают от дубликатов даже при разных ключах и разных администраторах.

RLS `version_visualizations` остаётся designer-only. Для этих фиксированных
концепций сервер дополнительно выводит формат из точного SHA-256 разрешённого
preview-файла. Эта привязка не зависит от имени и применяется после RLS-чтения
метаданных. Явная сохранённая настройка версии имеет приоритет. Изменение файла
даёт другой SHA и не может подменить утверждённый объект.

Импорт не создаёт аккаунты, решения, проверки ready, раунды или производственные
комплекты. Они допустимы только как реальные последующие действия сотрудников.
Удаление неизменяемых файлов и аудита не добавлено. Для завершения работы с демопроектом
используется существующее редактирование проекта → **Архивирован**. Для рабочей выборки используйте фильтр «Активные». История
сохраняется; повторный импорт не выводит проект из архива.

## Разные этапы — только изолированная демонстрация

На запущенном локальном restricted-сервере, после обычного локального seed:

```bash
PACKAPPROVE_TEST_ORIGIN=http://127.0.0.1:3030 npm run seed:showcase-stages
```

Скрипт проверяет localhost, порты PostgreSQL 54322/Supabase 54321 и demo mode.
Удалённые сервисы запрещены. Он использует реальные API-входы, приглашения,
регистрацию, submit, review, round, decision и package.issue, не прямое изменение
статусов. Существующие дизайнер/допечатник назначаются по именам локального seed;
новые согласующие создаются только в изолированном стенде.

Этапы: SOLAR — черновик, MIRA — внутренняя проверка, VOLT — согласование,
LUMA — замечание с координатой и возврат, TERRA — утверждена, PINK — комплект.
Даже в этих файлах и решениях остаётся предупреждение DEMO. Скрипт не включён в
автоматическое развёртывание и не предназначен для production.

## Проверки

`npm run typecheck`, `npm test`, `npm run build`, `npm run test:e2e`.
Новые тесты проверяют реальные PNG/PDF и пропорции, соответствие SHA, права,
подтверждённый UI-импорт, повтор без дублей, неизменность отдельного заказа
«Кола Зеро», сохранённые версии после reload, приватный и публичный WebGL,
отсутствие приватных API-запросов, полный оборот кнопками камеры и мобильное
отсутствие горизонтального переполнения. Все изменяющие проверки имеют локальные
guards. Готовые скриншоты — в `docs/showcase` после браузерной проверки.

Результат финальной локальной проверки: TypeScript и production build прошли;
101 Vitest; 62 passed / 2 прежних skipped в полном Playwright (609,4 с),
SQL/RLS и проверка миграций в scratch-БД прошли. Общий CI-job получает 45 минут
для двух полных прогонов с расширенной WebGL-галереей; глобальный таймаут
Playwright и существующие ограничения безопасности сохранены.
