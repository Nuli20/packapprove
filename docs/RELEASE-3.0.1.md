# PackApprove 3.0.1 — готовность изменений

Открытие созданного приглашения падало под ограниченным PostgreSQL login: публичный обработчик обращался напрямую к RLS-таблицам. Теперь проверка токена и фиксация регистрации выполняются узкими серверными capability-функциями. Анонимным пользователям не выдаются SELECT/UPDATE или EXECUTE этих функций. Вход и роль приглашённого сотрудника проверены настоящим браузерным сценарием, включая production-сборку.

## Изменения

- Три SECURITY DEFINER-функции с фиксированным search_path и серверным EXECUTE; хеш токена, срок, одноразовость, проверка подтверждённого Auth UUID, атомарные профиль/членство/принятие/аудит. Обработка сбоя Auth, rollback профиля, неоднозначного COMMIT и ошибки автологина. Существующий аккаунт не переписывается.
- Новые ссылки `/invite#token=…`, POST проверки и поддержка старых `?token=…`. Токены не попадают в новые HTTP URL и application logs. Понятные ошибки, пароль с подтверждением, loading и ссылка на вход.
- Три коротких шага проекта: заказчик/заказ → команда → макеты/сроки. Встроенные компактные формы клиента и приглашений; значения сохраняются между шагами. Пустые списки блокируют продолжение и предлагают корректное действие. Добавлены focus trap, Escape, возврат фокуса и стабильные доступные имена полей.
- `/demo`: шесть настоящих кабинетов, реальные HttpOnly Auth-сессии и RLS. В отдельном локальном Supabase — три производственных формата и четыре сценария: подготовка V1 дизайнером, ожидание клиента, проверка V2, переданный комплект. Старые проекты сохранены, повторный seed не сбрасывает действия пользователя.
- Onest с локальными Cyrillic/Cyrillic-ext шрифтами, тёплые поверхности, радиусы 12–18 px, компактные таблицы и менее шумный интерфейс. Убраны повторяющиеся рекламные и SHA-256-подписи из кабинета. SHA-256 осталась в версиях, решениях и производстве.
- 3D остаётся внутри сохранённой версии: 2D / 3D / сравнение. Три модели выбираются явными кнопками с силуэтами. `/can-lab` сохранена отдельно и убрана из основной навигации кабинета. Immutable файлы, решения, RLS и production gates не менялись.

## Публикация

1. Review ветки `fix/packapprove-invitations-and-demo-ux`. Основа синхронизирована с `origin/main` `2233bb6` (merge PackApprove 3.0); существующая работа не перезаписана.
2. Backup и отдельный staging Supabase. Из migration owner выполнить `npm run db:plan`, проверить **новую** `202610250003_invitation_capabilities.sql`, затем `npm run db:setup` на staging.
3. Проверить ACL/RLS read-only SQL из `supabase/checks`, реальные одноразовые ссылки и существующий email. Runtime login остаётся ограниченным и должен иметь SET ROLE packapprove_app. Новых production secrets не требуется.
4. После отдельного разрешения применить additive migration к production **до** новой версии API. Seeds и изменяющие тесты на production запрещены.
5. Только после проверки staging согласовывать merge/deploy. Эта задача не меняла production secrets, БД или main и не выполняла merge.

Откат не удаляет людей и историю: [rollback SQL](../supabase/rollback/202610250003_invitation_capabilities.sql) временно отзывает EXECUTE для регистрации. Профили/членства/принятые приглашения сохраняются. Подробный порядок восстановления — в INVITATIONS.md.

## Ограничения

- Публичный демо-деплой всех ролей не развёрнут. Демо-допуск сейчас намеренно ограничен локальным изолированным Supabase; включение одного флага против cloud production не работает. Для удалённого демо нужен отдельный проверенный deployment и механизм допуска отдельного Supabase project.
- Production Vercel/Supabase/SMTP не тестировались и не менялись. Для приглашения используется настоящая одноразовая ссылка, а не заявление об отправленном письме.
- Auth и SQL не образуют распределённую транзакцию. Неопределённый исход сохраняет Auth identity и может потребовать проверки администратором; действующие аккаунты автоматически не удаляются.
- Публичный rate limit действует на инстанс. Смена роли через `/demo` входит другим fixture-аккаунтом и не подменяет роль существующего пользователя.
- Модели банок приблизительные; 3D RGB не является цветопробой. Лимит upload 25 MiB, без TUS; эти ограничения 3.0 сохранены.
- Mobile проверен в Chromium с эмуляцией iPhone, не на физическом Safari. Скриншоты и видео получены реальным WebGL2 через SwiftShader.
