# Native file picker — исправление загрузки

Раньше область загрузки была label с маленьким нативным input, без отдельной кнопки и явного статуса выбранного файла. Старые E2E использовали setInputFiles напрямую и не подтверждали пользовательское открытие диалога. На исходном коде в Chromium клик по label вызывал chooser; конкретный отказ браузера пользователя локально не воспроизведён. Блокирующий overlay при проверке не обнаружен. Исправление устраняет зависимость от label и его оформления.

## Что изменено

- Общий `DesignFilePicker` используется в «Новой версии» и в 3D Studio. Видимая кнопка `type=button` синхронно вызывает `inputRef.current.click()` внутри пользовательского обработчика. Нет асинхронного ожидания до открытия chooser и нет прозрачного input поверх кнопки.
- До выбора — «Выбрать файл», после — «Заменить файл». Отображаются настоящее имя, размер и статус. Можно убрать выбранный файл. Сброс input.value позволяет выбрать тот же файл повторно; отмена диалога сохраняет текущий выбор.
- Предпросмотр и производственный файл обязательны, исходный файл необязателен. Проверка использует выбранные File objects, а не required на скрытом input. При отсутствии файла видны общая и адресная ошибки; фокус переводится на кнопку выбора. Список изменений остаётся обязательным.
- При выборе выполняются проверки размера 1 байт–25 MiB, фактического PDF/PNG/JPEG MIME, ограничений изображений и вычисление SHA-256. Асинхронный результат устаревшего выбора не подменяет новый. Сохранение блокируется на время проверки/загрузки.
- До «Сохранить» в Storage ничего не отправляется. Затем остаётся существующая схема: signed quarantine PUT в private Supabase Storage → маленький command JSON с uploadId → серверная проверка размера/MIME/SHA/прав → новая immutable версия. Все параллельные PUT завершаются перед разблокировкой формы, в том числе при ошибке одного из них.
- Удалены неиспользуемые `.upload-label` и `.can-upload` CSS; новый компонент имеет отдельные стили, кнопки минимум 44 px и корректный порядок Tab. Модальное окно имеет одну прокрутку и закреплённые действия.
- RLS, роли, SQL, согласования, техническая готовность и производственные комплекты не изменялись. Миграция не требуется.

## Фактическая проверка

`tests/e2e/native-file-picker.spec.ts` работает с отдельным локальным Supabase. Каждый desktop/mobile сценарий получает **6 настоящих filechooser events**: недопустимый JPEG, PNG, замена PNG на PDF, производственный PDF, необязательный JPG и PNG в 3D Studio. Используются click/tap, Tab/Shift+Tab, Enter и Space; force click не применяется.

Тест проверяет отсутствие upload-запросов до сохранения, понятные ошибки обязательных полей, отклонение поддельного JPEG, показ имени/размера/статуса, создание V1 с PDF/JPG и V2 из 3D с PNG, сохранение после reload и неизменность файлов V1. Все 5 сохранённых объектов скачиваются через защищённый endpoint, их SHA-256 сравнивается с исходными байтами. В command передаются uploadId, без Base64.

Typecheck, production build и 71 интеграционный/unit тест прошли. Полный E2E-прогон: **24 passed, 2 skipped** (повторные mobile API мутации покрыты на desktop). Настоящие скриншоты — в [галерее](review/native-file-picker/README.md). Mobile — эмуляция iPhone в Chromium; физический Safari в этой среде не проверялся. Production не использовался для изменяющих тестов.

Скриншоты тест пишет в игнорируемый test-results. В review добавляются только результаты успешного прогона; evidence JSON содержит реальные UUID/хеши локальных demo-версий, без cookies, паролей или signed tokens.
